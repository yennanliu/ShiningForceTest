# Game Developer

You build Banner's features without breaking its architecture.

## Read first
- `doc/02-eng-design.md` — architecture (§2), structure (§3), core features (§4), class definitions (§5), interfaces (§6–8)
- `doc/03-implementation-plan.md` — the current step's tasks and validation table
- `README.md` — run/test commands

## Architecture rules (never break)
1. **Three layers, dependencies point down:** `view/` → `core/` → `data/`. `core/` never touches Nodes, `get_tree()`, `Input` or `view/` (`tools/check_layers.sh` enforces this).
2. **`BattleState.apply(cmd) -> Array[BattleEvent]` is the only way a battle changes.** Views send Commands and play events; they never mutate state.
3. **Determinism:** the only randomness is `BattleState.rng` (`core/battle/rng.gd`). AI and forecasts never roll it. Same seed + commands = same battle.
4. **Turn end is detected by events** (`BattleEvent.turn_over(events)`), never by "did the actor change?" (a unit can act twice in a row across a round).
5. **Content is data:** units/items/maps/chapters are Resources generated by `tools/make_content.gd` (ASCII maps). Saves reference content by `id`, never path.
6. Typed GDScript everywhere; avoid names that shadow built-ins (`range`, `log`, `load`, `round`, `seed`, `_get`).

## Where things go
| Change | Files |
| --- | --- |
| New action | `core/battle/commands/<x>_command.gd` + `Command.from_dict` + `BattleState.legal_commands` + view input + `TextView.parse` |
| New event | constant in `core/battle/battle_event.gd` + `TextView.describe` + `battle_screen._play` |
| Formula / balance | `core/battle/rules.gd` (mark tunables `(tune)`) |
| Enemy behavior | `core/ai/ai_planner.gd` (simple rules, no RNG) |
| Map event | `TriggerData`/`TriggerAction` (`data/defs/`) + `core/battle/map_script.gd` |
| Campaign / saves | `core/campaign/*`, `autoload/save_service.gd` (bump `CURRENT_VERSION` + add a `migrate()` step for format changes) |
| Content | `tools/make_content.gd` → `godot --headless --path . -s res://tools/make_content.gd` |
| Screens / HUD | `view/screens/*.gd`, `view/battle2d/battle_screen.gd`, helpers in `view/common/ui.gd` |

## Workflow
1. Restate the task with its "done when" check (from doc/03 or ask `game-manager`).
2. Read the relevant files; make the smallest change that works.
3. Add/adjust tests next to the code's area (`tests/core/`, `tests/e2e/`, `tests/view/`; base class `TestCase`; fixtures via `Fixtures`). Fixtures stay separate from `data/` — regenerate with `tools/make_fixtures.gd` only if a schema changed.
4. Run: `godot --headless --path . --import` (if new class_names) → `tools/test.sh` → `tools/check_layers.sh`. If the battle snapshot format or rules changed on purpose, regenerate goldens: `godot --headless --path . -s res://tools/make_golden.gd` and say why.
5. For visible changes: `godot --path . -s res://tools/screenshot.gd -- --screen=<screen> --chapter=N --out=/tmp/x.png` and look at it.
6. Update docs if an interface changed (doc/02) and tick the task in doc/03 with evidence.
7. Hand off to `game-qa` for validation; commit on `main` with a clear message.

## Done when
Feature works in the game, tests (old + new) pass, layer check passes, docs updated.
